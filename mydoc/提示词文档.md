# 套定额系统提示词文档

## 🎯 概览

系统使用 **DeepSeek 思维模式** + **工具调用** 来进行工程量清单的套定额匹配。

提示词分为两层：
1. **系统提示词** (`_ROLE_DESC_BS2024`) - 定义 AI 角色和推理步骤
2. **用户消息** - 具体的清单项信息和操作指令

---

## 📝 系统提示词（代码中的默认值）

**文件**: `api/routers/bs2024_match.py:80-121`  
**变量**: `_ROLE_DESC_BS2024`

### 完整内容：

```
你是专业的建筑工程造价工程师，精通深圳市建筑工程消耗量标准（SJG 171-2024）。
你的任务是将招标工程量清单（BOQ）中的清单项与{chapter_name}专业定额子目进行匹配（套定额）。
【重要】请全程使用中文进行推理和分析。
【重要】推理过程（thinking/reasoning）必须使用中文输出，不得使用英文。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【推理步骤】

Step 1: 解析清单项目特征，识别材料品种/规格/施工工艺
Step 2: 将项目特征拆解为 1-3 条施工工序
Step 3: 对每条工序从定额子目列表中找最匹配的子目
Step 4: 计算 qty_factor（纯单位换算）
  清单m³ ÷ 定额10m³ = 0.1
  清单m³ ÷ 定额100m³ = 0.01
  清单m² ÷ 定额100m² = 0.01
  清单m ÷ 定额100m = 0.01
  单位相同 = 1.0
Step 5: 调用 submit_matches 输出结果

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【变体选择优先级】

1. 材料品种/规格完全匹配
2. 施工工艺匹配（湿拌 vs 干混；泵送 vs 非泵送）
3. 尺寸规格区间覆盖清单值
4. 单位相同或可换算

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【置信度标准】

- high：项目特征完整，与定额完全对应
- medium：主要特征匹配，但有次要特征未明确
- low：关键特征缺失，只能猜测

medium/low 时 missing_info 必须说明缺少哪些特征。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【返回空数组的情形】

- 该清单项不属于 {chapter_name} 专业范围
- 所有候选定额置信度均为 low 且工作内容匹配度低
- 清单单位无法与定额换算
```

### 关键特性：

| 特性 | 说明 |
|------|------|
| **动态替换** | `{chapter_name}` 根据选中的定额专业自动替换 |
| **中文强制** | 对 DeepSeek thinking mode 的特殊要求 |
| **单位换算** | 详细列举常见的工程量单位换算规则 |
| **分级管理** | 置信度分为 high/medium/low 三级 |
| **空结果处理** | 明确指出何时返回空数组 |

## 🔄 提示词组装流程

### 完整系统提示词的组成：

```
1. 角色描述
   ↓
_ROLE_DESC_BS2024（或数据库激活的模板）

2. 定额知识库
   ↓
【专业说明】
  - 来自 bs2024_sections（intro 部分）
  - 包括工程分类、材料规格等

【工程量计算规则】
  - 来自 bs2024_sections（rules 部分）
  - 扣除项、不扣除项等

【定额子目列表】
  - 来自 bs2024_subitems（250+条）
  - 格式: [ID:代码] 名称 | 单位:单位 | 全费用:价格 | 工作内容
```

### 代码位置：`api/routers/bs2024_match.py:237-330`

```python
def build_bs2024_system_prompt(conn, chapter_ids):
    # 1. 从数据库读取激活的提示词模板（如有）
    tpl_row = cur.execute("SELECT content FROM prompt_templates WHERE is_active=TRUE")
    
    # 2. 使用激活模板或代码默认
    role_template = tpl_row[0] if tpl_row else _ROLE_DESC_BS2024
    
    # 3. 替换 {chapter_name}
    role = role_template.replace("{chapter_name}", chapter_name)
    
    # 4. 组装完整提示词
    prompt = f"""{role}

## 专业定额知识库

{专业说明}

{工程量计算规则}

## 定额子目列表（{chapter_name}，共 {N} 条）

{子目列表}
"""
    return (chapter_name, prompt)
```

## 🔧 提示词模板管理系统

### API 接口

| 方法 | 端点 | 功能 |
|------|------|------|
| GET | `/prompt-templates` | 列出所有模板 |
| GET | `/prompt-templates/active` | 获取激活模板 |
| GET | `/prompt-templates/{id}` | 获取单个模板完整内容 |
| POST | `/prompt-templates` | 创建新模板 |
| PUT | `/prompt-templates/{id}` | 修改模板内容 |
| POST | `/prompt-templates/{id}/activate` | 激活模板 |
| POST | `/prompt-templates/deactivate-all` | 取消所有激活（用代码默认） |
| DELETE | `/prompt-templates/{id}` | 删除模板（不能删除激活中的） |

### 数据库表结构

```sql
CREATE TABLE prompt_templates (
    id          SERIAL PRIMARY KEY,
    name        VARCHAR(200) NOT NULL,          -- 模板名称
    description TEXT,                           -- 描述
    content     TEXT NOT NULL,                  -- 提示词完整内容
    is_active   BOOLEAN DEFAULT FALSE,          -- 是否激活
    created_at  TIMESTAMP DEFAULT NOW(),        -- 创建时间
    updated_at  TIMESTAMP DEFAULT NOW()         -- 更新时间
);
```

### 使用示例

**创建新模板**：
```bash
curl -X POST http://localhost:8000/prompt-templates \
  -H "Content-Type: application/json" \
  -d '{
    "name": "套定额 v2.0",
    "description": "改进版本 - 增加了特殊场景处理",
    "content": "你是...(完整提示词内容)"
  }'
```

**激活模板**：
```bash
curl -X POST http://localhost:8000/prompt-templates/1/activate
```

**回退到代码默认**：
```bash
curl -X POST http://localhost:8000/prompt-templates/deactivate-all
```

## 💾 修改提示词的两种方式

### 方式 1：直接修改代码（立即生效）

1. 编辑 `api/routers/bs2024_match.py:80-121`
2. 修改 `_ROLE_DESC_BS2024` 的内容
3. 重启 API (`python -m uvicorn api.main:app --port 8000`)

**优点**: 简单直接  
**缺点**: 需要重启，无版本管理

### 方式 2：通过数据库模板系统（推荐）

1. **创建新模板** (POST `/prompt-templates`)
2. **在线编辑** (PUT `/prompt-templates/{id}`)
3. **激活模板** (POST `/prompt-templates/{id}/activate`)
4. **保留历史** (查询 created_at/updated_at)
5. **随时切换** (激活不同版本)

**优点**: 版本管理、无需重启、可快速切换

## 📊 提示词优化建议

### 1. 增加匹配示例

```markdown
【匹配示例】

清单项: 砖砌体（240mm厚，预拌砂浆 M7.5）
→ 定额: [ID:010102-1] 标准砖砌体 240mm 内墙
→ qty_factor: 1.0（m³ 对 m³）
→ confidence: high（特征完整）

清单项: 混凝土（C30，泵送）
→ 定额: [ID:020105-3] C30 混凝土（泵送）
→ qty_factor: 泵送+楼层高度系数
→ confidence: medium（缺少楼层高度）
```

### 2. 特殊场景处理

```markdown
【特殊场景】

■ 如果清单特征为"综合考虑"
  → 按该类定额的常见做法选择
  → 置信度标记为 medium
  → missing_info 注明"特征不详细"

■ 如果跨度/高度不在定额范围内
  → 向最近的范围选择，并按比例换算
  → 在 factor_explanation 中说明换算方式

■ 如果单位无法直接换算
  → 返回空数组
  → 在 missing_info 中说明"单位不兼容"
```

### 3. 常见错误预防

```markdown
【常见错误】

✗ 混淆基础和墙身（不同的定额代码）
  ✓ 以设计室内地面为界：下为基础，上为墙身

✗ 遗漏单位换算系数
  ✓ 例如 100m³ 的定额需要 × 0.01

✗ 选择不同专业的定额（如砌筑工程中选混凝土工程）
  ✓ 核对定额代码的首位数字（第一位表示专业）

✗ 忽视工序拆解，一条清单项对一条定额
  ✓ 一个清单项可能涉及 2-3 条不同工序的定额
```

## 🔍 现有提示词的质量评估

### ✅ 强项
