# 单条智能组价工作流优化计划

## Summary

当前实现不建议改成开放式 ReAct、Plan-exec、Plan-ReAct 或 MCP Agent。现有业务更适合继续采用“确定性 Workflow Agent + 局部 LLM Tool Calling”的模式。

当前 8 轮编排本质是业务工作流：

1. 编码核查：确定性 DB 查询
2. 项目特征完整性：LLM 判断
3. 标准工序：确定性 DB 查询
4. 定额候选：确定性 DB 查询
5. 套定额分析与结构化提交：LLM + tool schema
6. 人工对比评估：确定性规则
7. 换算判断：LLM + tool schema
8. 人工确认换算并写回：确定性写库

这个拆分方向是对的。组价属于高风险、强规则、强审计业务，不适合让模型自由规划和自由调用工具。

## Key Changes

- 保留当前主模式：后端固定编排步骤，LLM 只在需要专业判断的节点工作。
- 不引入完整 ReAct、Plan-exec、Plan-ReAct 作为主流程，避免模型越权、步骤漂移、结果不可审计。
- 把当前 Prompt Chain 升级为显式状态机 Workflow：
  - 每一步定义输入、输出、失败策略、是否可跳过、是否需要人工确认。
  - `pricing_task_runs.step_timings` 已经有基础，可继续扩展为 step status、retry、model usage、prompt version。
- 第 5 轮和第 7 轮继续使用“两段式”：
  - 先流式分析，给用户可见解释。
  - 再强制 tool call 输出结构化结果。
- 候选检索优先加强，不优先换 Agent 框架：
  - 第 4 轮候选目前主要依赖清单编码映射。
  - 后续可增加名称、特征、工序、章节、工料机相似度召回，再让 LLM 排序选择。
- MCP 不建议作为内部业务主链路技术：
  - MCP 适合把外部工具、数据库、文档服务开放给通用 Agent。
  - 当前 FastAPI 直接查 PostgreSQL 更简单、可控、低延迟。
  - 如果未来要给其他 Agent 或桌面工具复用组价能力，再把组价 API 封装成 MCP server。

## Implementation Direction

- 后端保持集中在 `api/routers/pricing_task.py`，但建议把大文件拆成 4 个模块：
  - workflow orchestration：8 步状态机与 SSE 输出
  - tools/retrievers：编码核查、工序、候选、换算规则、工料机查询
  - llm_steps：特征分析、套定额、换算判断
  - persistence：run/result 保存、确认、写回
- 增加 prompt/version 记录：
  - 每次运行保存 `prompt_version`、`model`、关键输入摘要、候选数量、输出 JSON。
  - 方便后续做命中率回归和 prompt A/B。
- 增加“候选不足/特征缺失”的业务闸门：
  - 候选为 0：不要进入套定额模型选择，直接返回缺候选原因。
  - 项目特征不完整：允许继续，但结果自动降置信度并标记人工复核。
- 第 7 轮换算判断建议继续放在人工确认后触发。
  - 因为换算依赖最终确认的定额，放在确认前会浪费成本且可能基于错误定额判断。
- 第 8 轮应保持人工确认写回，不让模型直接改库。

## Technology Choice

- 推荐主模式：Workflow Agent + Tool Calling + RAG/DB Retrieval。
- 可局部使用 Plan-exec 思想：只把业务计划固化为代码状态机，不让模型动态生成计划。
- 不推荐主流程 ReAct：组价工具集合固定，模型不需要反复自由观察和行动。
- 不推荐主流程 Plan-ReAct：会增加复杂度，但业务收益有限。
- 不推荐现在上 LangChain、AutoGen、CrewAI：当前 FastAPI + OpenAI SDK 已足够，框架会增加调试和状态持久化成本。
- MCP 暂不作为核心实现，只作为未来能力开放层。

## Test Plan

- 单元测试：
  - 编码截断 `_base_code`
  - 候选归一化 `_normalize_matches`
  - 换算结果归一化 `_normalize_conversion_check`
  - 人工对比 `_evaluate`
- 集成测试：
  - 候选为 0 的清单项
  - 特征缺失但有候选的清单项
  - 多定额命中的清单项
  - 人工确认后触发第 7 轮
  - 第 8 轮写回 qty_factor 和工料机调整
- 评测集：
  - 使用已有人工套定额工程作为 golden set。
  - 指标至少包括命中率、遗漏率、额外率、完全一致清单数、第 5 轮耗时、第 7 轮人工复核率。
- 回归验收：
  - 优化后第 5 轮命中率不能低于当前版本。
  - 候选召回增强后，额外错误不能明显上升。
  - 所有模型输出必须仍经过候选白名单校验。

## Assumptions

- 当前目标是提高单条组价准确率、可解释性和可控性，而不是构建一个开放式通用 Agent。
- 现阶段综合单价计算还不在该闭环内，当前重点仍是套定额、换算判断和人工确认。
- 人工确认是业务必要环节，不能被模型自动写回替代。
